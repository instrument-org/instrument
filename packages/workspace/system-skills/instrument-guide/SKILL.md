# Instrument guide

What a person can do in Instrument and where each thing is, so a question about the app gets a short answer with a link that takes them there. `reference.md` beside this file lists every page and row of Settings, every screen a link opens, and every keyboard shortcut, read off the app itself. Read it for any question about a setting or a shortcut, and take names and keys from it rather than from memory. The keys written here are the Mac's; give the Windows and Linux ones from `reference.md`.

`places.md`, also beside this file, has what each menu and bar offers, by place: the sidebar, tabs, a website's ⋮, the bookmarks bar, a chat and its reply box, the Chats page, Files, Apps and the command menu. Read its section (it opens with how) for a question about what a menu has, where an action is, or whether there is one.

This is not the whole app. Something not listed may still exist, so never tell the user Instrument lacks a thing because it isn't here, only when a line here says so. To find out, look where it would be: `places.md` for a menu, `instrument settings list` for a setting, `instrument window list` for tabs and tab groups. Still unsure, say so and name the likeliest menu or the command menu (⌘K), which finds settings, pages and commands by name; never make up a menu, button or key.

## Linking

A setting, a page of Settings, or a screen is linked the way anything else in the app is, a Markdown link to its own address, and it draws as a chip the user clicks to go there:

- A row of Settings: [Zoom](instrument://settings/zoom). Settings opens on its page with the row lit.
- A page of Settings: [Providers](instrument://settings/providers).
- A screen: [Keyboard shortcuts](instrument://screen/shortcuts).
- A project: `instrument://project/<id>`, with the id `instrument projects list` prints. Its details open over the window.

The label is the thing in the user's words, and the name in the address comes from `reference.md`. Give the keyboard shortcut beside the link when there is one. Answer the question first, then link where they would click through; a reply that is only a link makes them do the reading.

## Changing a setting

A setting the user asks to change is changed for them when `instrument settings` can: `instrument settings list` says what each one is, its value now and what it takes, and `instrument settings set <id> <value>` changes it at once. A card under the reply shows what changed, with Undo, so the reply says it in a few words. One the list marks as the user's, and every other row of Settings (permissions, sign-ins, keys, the plan, storage, clearing anything), is linked instead, with what to do there. [Notify when tasks finish](instrument://settings/notifications) is always, only while Instrument isn't in front (Only when not focused, the default), or never. A few it sets have no row of their own: ad blocking, the bookmarks bar and Ask for feedback. The model a chat runs on is the user's to pick, at the bottom right of its reply box. Never click through Settings to change one.

## The window

Instrument's window is a browser with chats in it. The sidebar down the left has Search (⌘K) at its top, then the projects, the pinned tab groups, New, and the window's other tab groups newest first. At its foot are the account, which opens Settings (it reads Settings when nobody is signed in), History, which lists tab groups closed lately, and Help. ⌘B hides it.

- **Tab groups**: each sidebar row is a group, named for its first chat, or for the left side's tab last in front when it has no chat, with what that tab says under the name and icons for its other tabs at the end of that line. A chat's icon has a green dot while something in it is unread, and is a question mark bubble while it waits on the user. A group has one side of tabs or two, side by side, and one side has the keyboard. ⌘N makes a new group, ⌘T a new tab in the side with the keyboard, ⇧⌘T reopens what was closed. New Tab in Split (⌥⌘N), the button at the top right of a group of one side, which reads Chat beside a tab that is not a chat, makes the second side; Close Split, the ✕ in its place then, closes a side. A side with several tabs has a row of them, and a tab's right-click menu there moves it to the other side (Move to Other Side), joins the sides, or moves the tab to a new tab group or window. Merge All Windows, in the Window menu, puts windows back together.
- **Every tab is a page with an address**: a chat, a website, a folder or file, or one of the app's own pages (Settings, Chats, Apps, History, Bookmarks, Extensions); Memory and Skills are pages of Settings. Websites, files and the app's own pages have a toolbar with Back, Forward, Reload and the address field, then the bookmarks bar once ⇧⌘B turns it on (a new tab always has it). A chat shows only its title and menu until ⌘L brings up the field, and what is opened from there opens beside the chat. On one of the app's pages a chip leads the field. On every page an address or a path typed in the field opens, and anything else searches the web with the [search engine](instrument://settings/search-engine) picked in Settings, where the words also go as they are typed while [Suggest searches](instrument://settings/suggest-searches) is on; each of the app's pages has its own search.
- **New Tab** is a new chat: the reply box in the middle of the tab, with Project beside its + to file it. Sending a message makes the tab that chat. An address or a path alone in the box opens there on Return, and ⌘Return sends it to the chat instead. The list under the box has the pages a word names and, last, a web search for the words.
- **Bookmarks**: the star at the end of the address field, or ⌘D, keeps a page, a file or a folder, on the bar unless another folder was picked last. A chat among several tabs is kept with Add to Bookmarks in its tab's right-click menu. Apps, Chats and Files are always first on the bar.
- **⌘K** opens the command menu, to find a chat, a page or a command.
- **Chats** (⇧⌘F) lists every chat, open or not, under Inbox, Drafts and Archived, with search, and the projects at the top of Inbox: [Chats](instrument://screen/chats). A chat picked there comes up in the tab group it is in, or opens in that tab, where Back returns to the list. Closed tabs come back with ⇧⌘T or from the History page (⌘Y).
- **Files** shows the files on this computer. Results nobody put anywhere else land in the Files folder of the Instrument folder, in a folder named for the work.
- **Web pages** open in Instrument's own browser. While Instrument works in a page, the page glows, and Take over stops it and hands the page to the user. Chrome extensions, 1Password among them, run in it, installed from the Chrome Web Store: [Extensions](instrument://screen/extensions). Clear Browsing Data…, in the History menu, clears whichever the user picks: the history of a time range, and the cache or the cookies and site data (which signs them out of sites), each all of it whatever the range.
- **Apps** is where services like Gmail, Notion or Linear are connected, so Instrument can work in them: [Apps](instrument://screen/apps). Its search takes any service, listed or not. A right-click on an app's tile tests the connection, names the account, connects another account to the same service, disconnects it, or removes it. On the app's page, the ⋯ by its name tests the connection or removes it, and the ⋯ on an account's row names, disconnects or removes that account.

## Chats and tasks

A chat is where the user talks to Instrument, as a tab like any other: a group can have several chats, and one chat can be open in several tabs. Closing the tab, group or window of a chat that is working, or waiting on an answer, asks first and then stops it (Stop and Close), and so does closing a page a chat is working in; to leave it working, keep its tab open and go to another. The chat itself is kept, in Chats. Instrument answers small things itself and starts tasks for longer work, each running on its own and reporting back to the chat. What a chat opens, a link clicked in it or a page or file its agent shows, opens beside it, on the right side of its group; what the user opens from a chat on the right side opens as the next tab there. A chat can wait on something, or check back on it, for up to two hours while the app stays open, and then write on its own; anything later goes in the user's calendar or reminders.

- **Reply box**: + adds files, or a folder to work in, and typing / offers the same, with the skills and apps to name. Dictate takes speech instead of typing, and needs the user signed in to Instrument.
- **Model**: the model a chat runs on is picked at the bottom right of its reply box. The one picked in a new chat becomes the default for new chats. For a model that has them, the sliders button on its row in the picker, once it is the one chosen (Change effort and speed), has its thinking levels and Fast. The choice is the chat's, for that model, and once it isn't the default the reply box says it beside the model, where pressing it opens the same menu. More models come from the user's own plans and keys: [Providers](instrument://settings/providers).
- **Editing a sent message**: Edit message, the pencil that shows on pointing at a message the user sent, opens it in place with its files. Sending it takes the old message and everything after it out of the conversation, stops work in the chat started since, and gets a new reply; files stay as they are. The arrows under the message look back at its earlier versions. A chat's message to a task, one Instrument hasn't read yet, and those of an archived chat can't be edited.
- **Branch from here**, under any reply, starts a new chat with the conversation up to that reply.
- **Ask on a selection**: selecting text in an open file shows Ask, which notes what should change there. The notes gather at the foot of the file and go into a chat together.
- **The top of a chat** starts with its project, or Chats when it is in none: pressing the name opens that page, and the slash after it files the chat under another project. Its title follows, and pressing it renames the chat.
- **The chat's menu**, on the caret after the chat's title or a right-click on its tab, stops it while it works, marks it read or unread, renames, stars, archives, files it under a project, sends feedback about it, exports it, and deletes it: Export as Markdown… saves the whole conversation as a Markdown file where the user picks, and Delete Chat… asks first. A chat can't delete another one. Its Copy › For an Agent copies what another coding agent like Claude Code needs to pick up the chat.

The user can ask a chat to tidy up the others: rename them, archive them or bring them back, star them, or file them under a project. The chat does it with `instrument chats` (`instrument projects` names the projects), and a card under its reply says what changed, with Undo. It can tidy up the window's tab groups too, with `instrument window`: gather tabs into groups, close groups, pin or unpin them, and reorder the sidebar. Closing one this way asks nothing and leaves its chats working.

## What Instrument keeps

What the user reads and edits is plain files in their Instrument folder, which they can open in Files or any other app: the Files, Projects, Memory and Skills folders and `AGENTS.md`. [Instrument folder](instrument://settings/instrument-folder) says where it is and moves it. Files won't rename or delete those four folders; what is inside them is the user's to read and change. Instrument's own records (chats, drafts, apps) are in its hidden `.instrument` folder, which is not for editing.

- **Projects**: a folder each in the Projects folder, for filing chats. The sidebar lists them near its top, with a + for a new one that shows on pointing at the Projects heading, and a chat is filed under one at the top of its page, or with Project in its menu. A project's `AGENTS.md` has the instructions every chat filed under it follows and what stays true about the project. The user changes it in View project details, on the project's menu, in the file itself, or by asking Instrument. Each project is marked with an icon from the app's set or an emoji, on one of sixteen colors; the chat makes one with `instrument projects create`, changes the mark, the color, the name or the about line with `instrument projects set`, finds icons with `instrument projects icons`, and deletes one with `instrument projects retire`, as the app's Delete project does: it leaves the menus, its folder stays, and a card under the reply offers Undo. Renaming the folder renames the project, and other coding agents opened in the folder read the same `AGENTS.md`.
- **Instructions for every chat**: `AGENTS.md` at the top of the Instrument folder, which every chat follows. It has no screen in the app: the user edits the file, or asks Instrument to add to it.
- **Files**: what Instrument made for the user to keep, a folder each in the Files folder, named for the work. A chat filed under a project keeps its files in the project's folder instead. The folder button at the top right of a chat's page opens the folders it saved files in beside the chat, with a menu when there are several.
- **Drafts**: messages to Instrument the user started and hasn't sent yet, listed under Drafts in [Chats](instrument://screen/chats). A draft stays with the tab it was typed in, and closing the tab keeps one with anything in it. Instrument can read a draft and not change it; the user edits it in its tab. A draft the user asks Instrument to write (a post, a letter, a document) is their own work and never one of these.
- **Apps**: how each connected service is reached and what Instrument has learned about using it, kept in Instrument's own records, with no file to edit. Sign-ins and keys are kept apart. Instrument changes it as it works with the app, and the user asks a chat to change it, or manages the connection in [Apps](instrument://screen/apps).
- **Memory**: what Instrument remembers about the user, one Markdown file per memory in the Memory folder of their Instrument folder. Settings lists them to search, forget, or bring in from another AI: [Memory](instrument://settings/memory). Pressing one there, or a link to one, opens its file to read or edit; [Memory folder](instrument://settings/memory-folder) opens the folder in Files.
- **Skills**: recipes tasks use for a kind of work, and new ones the user asks for: [Skills](instrument://settings/skills). Each skill is a folder: clicking one in Settings that isn't Instrument's own opens its folder in Files, where the user reads or edits it, or asks Instrument to change it. Only skills in the workspace's own `Skills` folder can be deleted, from the "⋯" on their row.
- **Models**: Instrument works with its own plan, or the user's ChatGPT, Claude or Grok plan, or a provider with their own key: [Providers](instrument://settings/providers). Disable, in the ⋯ of a plan's or a key's card there, stops Instrument using it and keeps its sign-in or key, until Enable on the card.

## Coming from another AI

Someone moving to Instrument from ChatGPT, Claude, Gemini or another AI brings what it knows about them, can keep the plan they pay for, and starts new chats here:

- **Memories**: [Import from another AI](instrument://settings/memory-import). The user copies a question into the other AI and pastes its answer back, or picks ChatGPT, Claude, Gemini or Grok and Instrument opens it in a tab and asks there once they are signed in. Claude Code, Codex, Gemini CLI and opencode on this computer show there too, and are read from their own folders. Each one opens a new chat with the request in its reply box; once the user sends it, the chat saves the facts as memories and says what it kept and left out. The Memory list groups them under that chat, to be forgotten together if the user wants.
- **Their plan**: a ChatGPT, Claude or Grok plan they already pay for runs Instrument's chats once they sign in to it: [Providers](instrument://settings/providers).
- **Projects**: a project they kept there becomes a project here, its instructions in the project's `AGENTS.md` and its files in its folder.
- **Skills**: skills that Claude Code, Codex and other coding agents keep in their own folders on this computer are in [Skills](instrument://settings/skills) already.
- **Chats**: chats from another AI don't come over as chats here. An export of them is files like any other, which a chat can read to pick up where they left off.

## Something wrong

Send feedback…, in the Help button at the foot of the sidebar, sends the team a problem or an idea, about the chat on screen when there is one. Typing /feedback in the reply box, or Send Feedback… in a chat's menu or the Help menu, opens the same thing. The diagnostic log goes with it if the user wants: [Diagnostic log](instrument://settings/diagnostic-log).
