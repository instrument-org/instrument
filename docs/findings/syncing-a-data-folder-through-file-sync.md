# Syncing a data folder through third-party file sync: upper bound and painful truths

**Status:** research. The chat records it informed are built (per-device logs from 896a84342) and follow rules 1 to 4, 7, 11 and 12 below: one append-only log per session per device, hash-named blobs, a per-device index outside the folder, placeholders checked before reading, and a format version. They depart in three places: one growing file per session and device rather than a sealed segment per launch, records ordered by their ids within a session rather than by a hybrid logical clock, and the records stay in the hidden `.instrument/` while the visible `Chats/` folders hold the Markdown people read. The point about a device restored from backup (rule 1) still applies: a copied device id must not keep appending to a log its other copy extended.

Scope: a desktop app plus an iOS companion that keep chats (append-only JSONL), a rendered Markdown copy per chat, small JSON settings, user-editable Markdown notes, write-once binaries, and agent output files in one user-picked folder, with a per-device SQLite index outside it. Research date 2026-10-14. "Unverified" marks claims I could not confirm against a primary source. "User report" marks forum or issue-tracker evidence that is not a vendor statement.

## 1. Per provider

### Summary matrix

| | iCloud Drive | Dropbox | Google Drive for desktop | OneDrive | Syncthing |
|---|---|---|---|---|---|
| Same file edited on two offline devices | One winner becomes the file; the loser is kept as a hidden `NSFileVersion` conflict version, not a visible file. Only "new-file" collisions produce `name 2.ext` | Visible copy `name (<user or device>'s conflicted copy YYYY-MM-DD).ext`; the last save becomes the copy | Keeps both; naming not documented by Google (unverified) | Visible copy with device name appended, `name-DEVICE.ext` | Older mtime renamed to `name.sync-conflict-YYYYMMDD-HHMMSS-DEVICEID.ext` |
| Merges appends | No | No | No | No | No |
| Delta upload of a changed file | Desktop yes, iOS no (2017 study) | Desktop yes, mobile no (2017 study) | No (2017 study) | Yes since April 2020 (desktop) | Yes, block based; appends efficient |
| Deleted file recovery | 30 days | 30 / 180 / 365 days by plan | 30 days in Trash | 30 days personal, 93 days work | None unless versioning is turned on per folder, per device |
| Placeholders | Optimize Mac Storage (dataless files); iOS downloads on demand | File Provider online-only; auto online-only on low disk | Streaming is the default; mirroring optional | Files On-Demand, mandatory on macOS 12.3+; Storage Sense can dehydrate on Windows | None, always real files |

### iCloud Drive

- **Edit conflicts are hidden, not visible.** Apple's TN2336: outside new-file collisions, "iCloud Drive automatically creates new versions for all other conflicts", picking "a winning version and keeping the other changes in a losing version". Apps must use `NSFilePresenter` plus `NSFileVersion` to see the losers, and should remove them or they keep syncing and eat quota. https://developer.apple.com/library/archive/technotes/tn2336/_index.html
- **What that looks like to an app that doesn't use NSFileVersion:** an Obsidian user reproduced it with airplane mode: "one version silently overwrites the other", and the loser only appeared ("ConflictTest 2.md") when the file was opened in TextEdit, which triggers Apple's conflict sheet (user report). https://forum.obsidian.md/t/understanding-icloud-sync-issues/78186 . Another app's issue: an unresolved conflict version was never read, so "Mac B's collection was gone on both Macs" (user report). https://github.com/brandonmartinez/WaveWrangler/issues/117
- **Saving before the cloud copy arrives can lose data with no conflict at all.** A developer reports that saving before `NSMetadataQuery` finished downloading returned "the NEW file (with no other versions or conflicts)"; no Apple reply (user report, Nov 2025). https://developer.apple.com/forums/thread/808133
- **Visible `name 2.ext` copies** come from new-file conflicts ("a bounced file name"), only in the document scope; if contents are identical, no bounced file is made. TN2336 above. Same pattern in Apple's user docs ("Seven Wonders 2"); versions you don't keep are deleted everywhere. https://support.apple.com/guide/mac-help/document-versions-conflict-icloud-drive-mac-mh40780/mac . A common trigger is a device creating `file.ext` when the cloud already has one it hasn't downloaded yet (user report, 2016). https://www.alansiu.net/2016/08/30/icloud-sync-creating-duplicate-files-when-saving/
- **Folder moves and recreation:** in 2015 tests, deleting and re-creating a folder on one device while another changed files inside it split it into "Main" and "Main 2"; after an Apple fix the result became "File" and "File 2" copies instead. https://mentalfaculty.com/blog/archive/tumblr/the-mysterious-case-of-icloud-drive-and-the/
- **Deletion:** recoverable for 30 days from Recently Deleted or Data Recovery on iCloud.com. https://support.apple.com/guide/icloud/recover-deleted-files-mmae56ea1ca5/icloud
- **Excluded names:** `.nosync` and `.tmp` extensions (and their folder contents), `.DS_Store`, names starting "(A Document Being Saved", `~$*`, `desktop.ini`, `Icon\r`, `Dropbox`, and others. https://eclecticlight.co/2026/01/06/exclude-or-include-items-in-backup-search-icloud-drive-and-quicklook-preview/
- **Dot folders do sync:** Obsidian's `.obsidian` config folder syncs via iCloud and Obsidian waits for it on iOS. https://forum.obsidian.md/t/ios-icloud-slow-to-start-waiting-for-icloud-to-synchronize-obsidian-configuration-files/50827?page=7 . The iOS Files app and iCloud.com hide them (user report). https://discussions.apple.com/thread/255263958
- **Symlinks:** a 2021 security write-up stored and shared symlinks through iCloud Drive; no Apple statement found (unverified for current releases). https://breakpoint.sh/posts/files.app-symbolic-link-following
- **Packages:** handled as single documents (TN2336 talks about "files and file packages").
- **File and path limits:** no published file-count limit found (unverified). Item count drives work: changing Optimize Mac Storage makes FileProvider walk every item. https://eclecticlight.co/2024/03/11/icloud-drive-in-sonoma-optimise-mac-storage-or-not/
- **Eviction:** with Optimize Mac Storage on, iCloud Drive is a nonreplicated File Provider and files can become dataless; off, it is replicated with no eviction. https://eclecticlight.co/2023/11/21/icloud-drive-in-sonoma-fileprovider-and-eviction/ , https://eclecticlight.co/2026/05/09/explainer-file-provider-and-cloud-services/ . macOS 15 and iOS 18 added per-folder "Keep Downloaded". https://www.macworld.com/article/2378054/ios-18-macos-sequoia-icloud-keep-downloaded-option.html . A 328-note vault had "511 of 689 files" dataless and Obsidian stalled on each read. https://jasoncameron.dev/posts/obsidian-slow-startup-icloud
- **Windows:** Obsidian's docs warn "iCloud Drive on Windows may lead to file duplication or corruption." https://obsidian.md/help/sync-notes

### Dropbox

- **Conflicts:** "The editor's username, 'conflicted copy', and the save date will be added to the filename"; "The last version saved will always appear as the conflicted copy"; no merge. https://help.dropbox.com/organize/conflicted-copy . Real examples: `manifesto (Work Macbook's conflicted copy 2014-10-22).txt`. https://www.engadget.com/2013-02-20-finding-dropbox-conflicted-copy-files-automatically.html . A 2026 variant adds "(shared folder conflict)" (user report, same search; unverified).
- **Case:** names differing only by case get "(Case Conflict)" appended locally, even on Linux. https://help.dropbox.com/organize/case-conflict
- **Moves:** Sync Engine Classic "duplicates each directory" on conflicting moves; Nucleus (2020) keeps the originals and the first uploaded move wins. https://dropbox.tech/infrastructure/rewriting-the-heart-of-our-sync-engine . Kleppmann et al. observed Dropbox duplicating a concurrently moved directory. https://martin.kleppmann.com/papers/move-op.pdf (sec. 2.1)
- **Deletion and versions:** 30 days (Basic, Plus, Family), 180 days (Professional, Essentials, Standard, Business), 365 days (Advanced, Business Plus, Enterprise). https://help.dropbox.com/delete-restore/recover-older-versions
- **Not synced:** `desktop.ini`, `thumbs.db`, `.ds_store`, `icon\r`, `.dropbox`, `.dropbox.attr`, temp files starting `~$` or `.~`, plus "Symbolic links, Shortcuts, Junction points, Resource forks, Networked folders, Extended attributes" in that list. https://help.dropbox.com/sync/files-not-syncing . The symlink page says symlinks sync "as individual symlink files" and targets outside Dropbox are not followed (since 2019). https://help.dropbox.com/sync/symlinks . The two pages disagree on whether symlinks sync at all.
- **File count:** performance "can decline if you have more than 300,000 files synced"; soft limit. https://help.dropbox.com/storage-space/file-storage-limit
- **Delta sync:** desktop yes, mobile and web no (FAST '18 Table 1, tested April 2017). https://www.usenix.org/system/files/conference/fast18/fast18-xiao.pdf
- **Placeholders (macOS File Provider):** folder moves to `~/Library/CloudStorage`; files "not previously set to Make available offline may be automatically set to online-only when your hard drive is low on disk space"; "Packages now behave like regular files instead of directories". https://help.dropbox.com/installs/macos-support-for-expected-changes . TidBITS: after migration "assume that all your files and folders are online-only"; online-only files aren't indexed by Spotlight or backed up by Time Machine. https://tidbits.com/2023/03/10/apples-file-provider-forces-mac-cloud-storage-changes/

### Google Drive for desktop

- **Conflicts:** keeps both versions, but the naming is not in Google's help (sources disagree: "conflict" suffix, "[Conflict]", device name). A 2026 hands-on test found Drive kept both but the result was "less self-explanatory" than Dropbox's. https://www.makeuseof.com/tried-break-google-drive-onedrive-dropbox-syncthing/ . Naming: unverified.
- **Drive is ID-based and allows duplicate names in one folder**, so "it's not possible to optimistically create a file and test if it already existed". https://freefilesync.org/forum/viewtopic.php?t=6483 . How Drive for desktop maps two same-named cloud items to local names: unverified.
- **Moves:** in Kleppmann's test of concurrent moves forming a cycle, one Google Drive replica showed a persistent "unknown error". https://martin.kleppmann.com/papers/move-op.pdf (sec. 2.2)
- **Saving over a file** reportedly creates a new file with a new link (TidBITS commenter, user report). https://tidbits.com/2023/03/10/apples-file-provider-forces-mac-cloud-storage-changes/
- **Streaming vs mirroring:** streaming keeps files "only available online unless specifically made available offline" and they are only accessible while Drive for desktop runs; mirroring keeps everything local. Shared drives can only be streamed. https://support.google.com/drive/answer/13401938?hl=en . On macOS 12.1+ streaming uses File Provider. https://support.google.com/drive/answer/16631477?hl=en . On Windows the streamed drive is a virtual drive that reports a FAT file system (4 GB file cap). https://support.google.com/a/answer/2490100?hl=en
- **Deletion:** Trash auto-deletes after 30 days. https://support.google.com/drive/answer/2375102
- **Delta sync:** none on any client in the 2017 study (FAST '18 above); current behavior unverified.
- **Item limits:** a 5-million-item creation cap was imposed in 2023 and rolled back; shared drives are capped at 400,000 items. https://www.androidcentral.com/apps-software/google-drive-5-million-file-limit
- **Dot files, symlinks, packages:** no Google documentation found (unverified). Dot folders appear to sync (a `.lock` folder synced in a Joplin issue). https://github.com/laurent22/joplin/issues/3381

### OneDrive

- **Conflicts:** non-Office files are kept as two copies, the local one with the device name appended (2026 test above). A user saw thousands renamed `ABCD-PC1.lua` / `ABCD-PC2.lua` after re-enabling OneDrive. https://learn.microsoft.com/en-us/answers/questions/5440539/onedrive-has-copied-and-renamed-thousands-of-files
- **Limits:** "we recommend syncing no more than a total of 300,000 items"; "OneDrive doesn't support syncing using symbolic links or junction points"; case-sensitive volumes unsupported; `.tmp` files and `desktop.ini`/`.ds_store` don't sync; reserved names `.lock`, `CON`, `PRN`, `AUX`, `NUL`, `COM0-9`, `LPT0-9`, `_vti_`, `desktop.ini`, `~$*`; 400-character decoded path limit, 255 per segment. https://support.microsoft.com/en-us/office/restrictions-and-limitations-in-onedrive-and-sharepoint-64883a5d-228e-48f5-b3d2-eb39e07630fa
- **Hidden files:** "hidden and temporary files display the 'syncing' status, but they aren't synced by OneDrive" (Windows hidden attribute, not a leading dot). https://learn.microsoft.com/en-us/sharepoint/troubleshoot/sync/folders-incorrectly-show-status-syncing
- **macOS:** since macOS 12.3 File Provider is the only Files On-Demand mode and "cannot be disabled"; packages sync as a single file with a hidden `.pkgf` extension; the post claims symlink support, which contradicts the restrictions page (from the post's search snippet; I could not fetch the body). https://techcommunity.microsoft.com/blog/onedriveblog/inside-the-new-files-on-demand-experience-on-macos/3058922
- **Windows dehydration:** Storage Sense can make files online-only if unopened for 1 to 60 days; on Windows 11 22H2+ the OneDrive default is 30 days once Storage Sense runs. https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/manage-drive-space-with-storage-sense
- **Deletion:** 30 days personal, 93 days work or school. https://support.microsoft.com/en-us/onedrive/restore-deleted-files-or-folders-in-onedrive
- **Delta sync:** all file types since April 2020. https://office365itpros.com/2020/04/28/onedrive-differential-sync/

### Syncthing

- **Conflicts:** "one of the files will be renamed to `<filename>.sync-conflict-<date>-<time>-<modifiedBy>.<ext>`"; the older mtime loses; ties go by device ID; conflict files propagate as normal files and can nest; in modify-vs-delete, if the delete wins the modified file becomes a conflict copy. https://docs.syncthing.net/users/syncing.html . The v1.0 FAQ said the modified file always won; behavior changed across versions. https://docs.syncthing.net/v1.0.0/users/faq.html
- **Writes:** "Syncthing never writes directly to a destination file"; temp files are `.syncthing.<name>.tmp` (`~syncthing~<name>.tmp` on Windows), kept up to a day. The watcher batches changes for 10 s and delays deletions 1 min. Same page.
- **Renames and appends:** "renaming a file will not cause a retransmission"; "appending data to existing files should be handled efficiently". Symlinks synced "except on Windows, but never followed". https://docs.syncthing.net/users/faq.html
- **Deletions:** propagate everywhere; versioning (trash can, simple, staggered) is off by default, per folder per device, and only archives changes received from remote devices. https://docs.syncthing.net/users/versioning.html
- **Case:** paths are case-sensitive; collisions on case-insensitive systems are reported as case conflicts (syncing page above).
- **iOS:** "no plans ... to officially support iOS" (FAQ above). Third-party Möbius Sync "can only connect to other devices whilst the app is open, for a short time thereafter, and whenever it is triggered to run briefly in the background". https://mobiussync.com/faq/

### On-demand files and an app reading files it didn't recently open

- **macOS:** a dataless file is materialized when read, and the read blocks in the kernel while the provider downloads (stack through `apfs_materialize_dataless_file_ext`). https://github.com/hikarinessa/onyx/issues/107 . Offline, Obsidian users hit "File system operation timed out". https://forum.obsidian.md/t/obsidian-not-opening-mac/81406 . With `setiopolicy_np(IOPOL_TYPE_VFS_MATERIALIZE_DATALESS_FILES, ..., OFF)` reads fail with `EDEADLK` instead of downloading. https://keith.github.io/xcode-man-pages/setiopolicy_np.3.html
- **Windows:** reading a placeholder hydrates it; even attribute dialogs that read content trigger downloads. https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants , https://freecommander.eu/viewtopic.php?f=7&t=10572
- **Consequence:** a startup scan that reads every file turns into a download storm, and offline it either blocks or fails. Spotlight and Time Machine skip online-only files (TidBITS above), so "the folder is my backup" is false for evicted data.

## 2. iOS specifically

### iCloud Drive folders picked by the user

- **Picking and keeping access works.** Since iOS 13 `UIDocumentPickerViewController` with `.folder` returns a security-scoped URL that lets the app "recursively access the directory and all of its contents, which includes accessing any new items you add to the directory in the future"; save it as a `.minimalBookmark`; use a file coordinator for reads and writes; users can revoke access in Settings at any time. https://developer.apple.com/documentation/uikit/providing-access-to-directories
- **Bookmark traps:** after a reboot, a child URL built from a restored folder bookmark failed with "Operation not permitted" until access was started on the bookmarked URL itself (iOS 26.6). https://github.com/vinceglb/FileKit/pull/672 . iCloud Drive directory bookmarks made on iOS 13 stopped resolving on iOS 14 and Apple called it "functioning as intended". https://developer.apple.com/forums/thread/657988
- **Watching for changes is weak.** `NSMetadataQuery` on imported or picked folders returns nothing; DTS said the scope "doesn't behave as documented" (FB9631965); the workaround is `NSFilePresenter`, where only `presentedSubitemDidChange(at:)` works consistently. https://developer.apple.com/forums/thread/689468 . On iOS 18.4.1 a query on a user folder in iCloud Drive only saw root-level changes. https://developer.apple.com/forums/thread/783958
- **No background:** presenters must be removed when backgrounded or the app is killed, and "If you are suspended, it won't resume (or relaunch) you." https://developer.apple.com/forums/thread/718488 , https://developer.apple.com/library/archive/releasenotes/Foundation/RN-FoundationOlderNotes/index.html
- **Downloads are the app's job.** On iOS a remote file usually stays a placeholder until requested; use `startDownloadingUbiquitousItem(at:)` (files only, not folders) or a coordinated read; `startDownloading` reports success even when it fails offline. https://fatbobman.com/en/posts/advanced-icloud-documents/
- **Staleness since iOS 18.4:** a file in the "Downloaded" state "may remain ... for an indefinite period" without pulling the current version until `startDownloadingUbiquitousItem` is called again; no Apple reply (FB17662379). https://developer.apple.com/forums/thread/785030
- **Use the app's own iCloud container when possible.** Obsidian requires the iOS vault inside the Obsidian folder in iCloud Drive (the one with the app icon) "or syncing issues may occur". https://obsidian.md/help/sync-notes . Even there, Obsidian's CTO calls Apple's API "super limited, and also quite buggy": the scan "iterates through every single file", and "Apple has provided no API to know whether [Keep Downloaded is] enabled". https://forum.obsidian.md/t/ios-icloud-slow-to-start-waiting-for-icloud-to-synchronize-obsidian-configuration-files/50827?page=7

### Dropbox, Google Drive, OneDrive on iOS

- **Folder picking needs provider opt-in.** Third-party providers are greyed out in the folder picker unless their extension sets `NSExtensionFileProviderSupportsPickingFolders`, which Apple barely documents. https://developer.apple.com/forums/thread/691738 , https://github.com/nextcloud/ios/issues/1858 , https://github.com/haiwen/seafile-iOS/issues/237
- **Dropbox:** "As of May, 2024 Dropbox has updated their app to implement a fully-featured iOS Files integration"; "many major file storage providers (FSP) still do not support this functionality". https://ia.net/writer/support/library/cloud-storage/cloud-storage-iphone . Limits: no offline access from Files unless marked offline in the Dropbox app; "Opening folders with more than 10,000 files or folders" unsupported; two simultaneous editors "create conflicted copies". https://help.dropbox.com/integrations/ios-files-app . Making a whole folder available offline needs a paid plan, and offline files don't refresh on cellular by default. https://help.dropbox.com/sync/access-files-offline
- **Google Drive and OneDrive:** Ulysses says folders from "OneDrive and Google Drive" can't be added because those providers don't support it on iOS. https://help.ulysses.app/external-folders . Craft: on iOS "Apple currently doesn't allow access to most third-party sync services ... The only available option in this case is iCloud Drive." https://support.craft.do/hc/en-us/articles/6696361366813-External-Locations . No 2025 or 2026 evidence of change found (unverified either way).
- **Freshness:** a provider's folder only updates for other apps when the provider signals its enumerator; a consumer app can't force it. https://developer.apple.com/forums/thread/810711 . So even where picking works, expect fetch on demand, not a watched synced tree.

### Obsidian, officially

- iOS and iPadOS: "Recommended options are Obsidian Sync and iCloud"; Dropbox, Google Drive, OneDrive, and Syncthing are unsupported on iOS. Reason: "Unlike some note-taking apps that access one file at a time, Obsidian requires access to the entire vault for its features (e.g., updating links when renaming a file). This makes it difficult for some services to function reliably with Obsidian." It also says "Avoid syncing the same vault across multiple services" and to use Keep Downloaded or disable Optimize Mac Storage. https://obsidian.md/help/sync-notes
- Obsidian Sync itself excludes every dot file and folder except `.obsidian`. https://obsidian.md/help/sync/settings
- Reported iCloud failure modes: duplicates when the vault opens before sync finishes, moves triggering duplicates, files "sync pending indefinitely", iOS daily notes duplicated because the app creates the file at startup before the iCloud copy arrives. https://forum.obsidian.md/t/icloud-sync-issues/28320 . iOS evicting hundreds of vault files (user report). https://forum.obsidian.md/t/can-i-stop-having-to-re-download-icloud-vault-files/29498 . Slow first load because the check "takes proportionally longer the more files you have" (WhiteNoise, staff). https://forum.obsidian.md/t/ios-icloud-slow-to-start-waiting-for-icloud-to-synchronize-obsidian-configuration-files/50827?page=7

## 3. Prior art

- **Obsidian:** plain files; iOS limited to iCloud (own container) or Obsidian Sync, which is its own server with its own exclusions. Sources in section 2.
- **Logseq:** file graphs hit "Data loss when using Logseq sync with multiple clients", and "Building real-time collaboration on top of Markdown files is extremely challenging" because adding a block rewrites the whole file; the DB version keeps SQLite as the source of truth with Markdown export. https://discuss.logseq.com/t/why-the-database-version-and-how-its-going/26744 . iCloud reports: an old Mac copy uploaded over the iPad's day of edits (https://github.com/logseq/logseq/issues/5901); "Which version do you want" choices deleting data on other devices (https://github.com/logseq/logseq/issues/7748). A 2026 post says the file app was split off as "Logseq OG" in maintenance mode (third-party site, unverified). https://logseq.io/page/b2ad9ce1-9cb7-4436-8083-54cb4516d324/df4dc09d-0a12-4c87-904e-22a9bf4c350a
- **Joplin:** its own sync engine writes one file per item to a dumb target (`<id>.md` in Dropbox). https://discourse.joplinapp.org/t/why-do-i-get-a-conflict-when-synchronizing/3089 . Conflicts copy the local note into a Conflicts notebook and take the remote. https://joplinapp.org/help/apps/conflict/ . A newer line-based three-way merge stores a base per sync target; word-level merge "could silently duplicate text". https://joplinapp.org/help/dev/spec/conflict_auto_merge/ . `info.json` carries `version` and `appMinVersion`. https://joplinapp.org/help/dev/spec/sync . Cost: a file-system target synced by Syncthing breaks on lock files (https://github.com/laurent22/joplin/issues/9759), a Windows `desktop.ini` inside `.lock` broke sync (https://github.com/laurent22/joplin/issues/3381), and per-item files plus provider throttling make a 13k-item first sync fail on OneDrive (https://discourse.joplinapp.org/t/constantly-throttled-by-onedrive-cannot-sync-at-all-on-fresh-device/45071).
- **Zotero:** a data directory in Dropbox or Google Drive "will almost certainly lead to database corruption and potentially data loss". https://www.zotero.org/support/preferences/advanced . A forum explanation cites `locking_mode=EXCLUSIVE` being invisible to sync tools (thread not pinned down; unverified).
- **DEVONthink:** refuses to open or create databases in cloud-synced folders ("It is not and never has been data safe"); syncs through its own sync store via the provider's API. https://www.devontechnologies.com/blog/20230912-where-store-databases
- **Day One:** dropped Dropbox and iCloud sync: "we had thousands of cases of data loss and duplication with iCloud and Dropbox"; Dropbox gave duplicate entries, iCloud gave data loss. http://help.dayoneapp.com/en/articles/436081-day-one-sync-faq
- **Bear:** "We chose CloudKit instead of a file based solution like iCloud, DropBox, or Google Drive because it performs much faster." https://bear.app/faq/syncing-privacy/
- **Things:** built Things Cloud in 2011 instead of iCloud; third-party services unsupported. https://culturedcode.com/things/blog/2011/07/cloud-sync-beta/ , https://culturedcode.com/things/support/articles/2803586/
- **Craft:** own sync; its External Locations (third-party folders) are "not recommended for multi-device use" and "can lead to data conflicts and data loss". Craft link above.
- **Ulysses and iA Writer:** both allow external folders where the provider supports folder access (iCloud, Dropbox since 2024); Ulysses makes no automatic backups of external folders. Links in section 2.
- **Apple Notes:** CloudKit records, not files (not researched further).
- **Anytype:** CRDT DAGs over its own any-sync nodes, with separate file nodes for blobs. https://tech.anytype.io/any-sync/overview
- **Apple's own per-peer logs over iCloud Drive:** Core Data iCloud wrote one transaction log per save per peer into the ubiquity container, each uploaded whole; it was deprecated in iOS 10. https://developer.apple.com/library/archive/documentation/DataManagement/Conceptual/UsingCoreDataWithiCloudPG/Introduction/Introduction.html , https://mjtsai.com/blog/2016/06/17/the-deprecation-of-icloud-core-data/ . Ensembles, built in response, made cloud files immutable ("Once a file is added to the cloud, it should not be moved, and the contents should not be changed") and ordered change sets with vector clocks; it said many iCloud problems came from modifying the same file on multiple devices. https://mentalfaculty.tumblr.com/post/62909673342/introducing-ensembles-core-data-sync-the-way-it . Lesson: per-peer logs were necessary but not enough; merge semantics, identity, latency, and throttling still sank it.
- **CRDT over files:** tonsky: file sync is "dumb"; "In case of conflict, best case, you get two files. Worst, you get only one"; fix by giving each client its own file and appending operations in chunks. https://tonsky.me/blog/crdt-filesync/ . outl ran a move-tree CRDT over per-device `ops-*.jsonl` files on iCloud Drive to prove convergence, then moved to peer-to-peer for reach (Linux, Android) and privacy, not because of iCloud failures. https://avelino.run/from-icloud-to-peers/
- **Ink & Switch:** with file sync "if the same file is edited on two different devices, the result is a conflict that needs to be merged manually"; format-agnostic sync is "a weakness (inability to perform format-specific merges)"; CRDTs "can sync their state via any communication channel" and they tried "a 'sneakernet' implementation of copying files around with Dropbox and USB keys" before settling on Hypercore. https://www.inkandswitch.com/essay/local-first/

## 4. Design patterns that survive third-party file sync

- **One writer per file.** The only way to avoid provider-level conflicts is to never write the same file from two devices (tonsky, Ensembles above). This sidesteps iCloud's hidden losers, Dropbox/OneDrive/Syncthing copies, and Google Drive's ambiguity in one move.
- **Write-once, immutable, uniquely named files.** Ensembles' rule above. Content hashes or ULIDs as names also defeat iCloud's new-file collisions, since two devices never create the same name with different content (and identical content is not a conflict per TN2336 and Syncthing's "content actually differs" rule).
- **Append-only logs vs whole-file rewrites.** No provider merges appends. Appends are cheap only where delta sync exists (Dropbox and iCloud desktop, OneDrive, Syncthing); mobile clients re-upload whole files (2017 study). Chunk the log into sealed segments so each sync unit stays small (tonsky). Readers must tolerate a missing or partial last line while a file is mid-write or mid-sync.
- **Atomic writes and temp files.** Syncthing itself uses temp-then-rename. Give your temp files names every provider ignores: `.tmp` extension (ignored by iCloud and OneDrive) plus a `.~` prefix (ignored by Dropbox), for example `.~settings.json.tmp`, in the same directory, then rename. Inference from the ignore lists above; verify per provider. Whether a rename-over keeps the provider's file identity and version history is unverified (Google Drive reportedly makes a new file).
- **Detecting conflict copies by name.** Patterns: Dropbox ` (<who>'s conflicted copy YYYY-MM-DD)` and `(Case Conflict)`; iCloud ` 2`, ` 3` before the extension (only for new-file collisions); OneDrive `-<DEVICENAME>` before the extension; Syncthing `.sync-conflict-YYYYMMDD-HHMMSS-<DEVICEID>`; Google Drive unknown. iCloud edit conflicts have no filename: on macOS and iOS you must ask `NSFileVersion.unresolvedConflictVersionsOfItem(at:)` (TN2336). From Electron that means native code.
- **Never put SQLite in the synced folder.** SQLite says copies are safe only "as long as there are no transactions in progress", the `-wal`/`-journal` must travel with the database, and deleting a hot journal corrupts it; it relies on file locking that sync tools don't honor. https://www.sqlite.org/howtocorrupt.html . Zotero, DEVONthink, and Bear above all keep the database local.
- **How many files.** Soft ceilings: 300,000 synced items (Dropbox, OneDrive); folders over 10,000 entries won't open in Dropbox via iOS Files; iCloud and Obsidian startup checks scale with total file count; Joplin's per-item files throttle on first sync at ~13k items. One folder with a few files per conversation is fine; one file per message or per key-value is not.
- **Detecting placeholders without downloading them.** macOS: `stat` `st_flags & SF_DATALESS` (`stat -f %Sf` prints `dataless`). https://keith.github.io/xcode-man-pages/chflags.2.html . Node's `fs.Stats` has no flags field; `blocks === 0 && size > 0` is a heuristic used in the wild but also matches APFS-compressed files (the Jason Cameron output shows `compressed,dataless`). iOS and macOS Foundation: `URLResourceKey.ubiquitousItemDownloadingStatusKey`; older iOS placeholders are `.<name>.icloud` files (fatbobman). Windows: `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS` (0x400000) and `FILE_ATTRIBUTE_RECALL_ON_OPEN` (0x40000, directory enumeration only), readable without hydrating. https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants , https://learn.microsoft.com/en-in/answers/questions/5307344/onedrive-how-to-identify-whether-a-file-is-synced

## 5. Bottom line

**Best achievable guarantee with two offline writers, using only someone else's sync:** if every file has one writer device or is write-once with a unique name, then once both devices reconnect and the provider delivers everything, no write is lost and every device can compute the same merged state (union of events by ID, ordered by a hybrid logical clock). That is the ceiling. It does not give:

- **Cross-file ordering or atomicity.** A chat's log segment, its attachment, and its settings arrive independently and in any order.
- **Timeliness.** Nothing wakes the iOS app; providers batch, throttle, and evict.
- **Identity under folder moves.** Concurrent moves duplicated on Dropbox Classic, wedged Google Drive, and split folders on old iCloud.
- **Safe shared mutable files.** For a user-editable note edited on two devices, the best case is a visible conflict copy (Dropbox, OneDrive, Syncthing, likely Google Drive) that the app must detect and three-way merge against a stored base. On iCloud the loser is hidden in `NSFileVersion`, or with an early save there may be no loser at all.

**Providers that make it worse:**

- **iCloud Drive:** hidden conflict versions, overwrite-before-download, eviction, the 18.4 staleness bug, and a broken `NSMetadataQuery` outside the app's container.
- **Google Drive:** ID-based duplicate names, undocumented conflict naming, streaming by default, no delta sync (2017), and a FAT virtual drive on Windows.
- **OneDrive:** placeholders are mandatory on Mac, Storage Sense can dehydrate files after 30 days, hidden files don't sync on Windows, and it has reserved names (`.lock`) and a 400-character path limit.
- **Dropbox** is the best documented. **Syncthing** has the cleanest semantics (real files, temp-then-rename, device-tagged conflicts) but relies on mtimes and has no deletion safety net by default.

**iOS companion, realistically:**

- **iCloud Drive:** yes, best inside the app's own iCloud container, foreground only. Read placeholders on demand and re-request downloads to dodge staleness.
- **Dropbox folder:** possible since 2024, but full offline folders need a paid plan and change visibility is weak.
- **Google Drive and OneDrive:** not as folders. Supporting them means the iOS app talks to their REST APIs itself, which is what Obsidian's Remotely Save plugin does.
- **Syncthing:** only through Möbius Sync or Synctrain into a local folder, with sporadic background sync.

**Note on the current layout:** the repo's documented layout keeps `chat.db` (SQLite) at `chats/<id>/.instrument/chat.db`. If `chats/` lands in the picked folder, that is the Zotero and DEVONthink failure mode. The `.instrument/` dot folder is also hidden in iOS Files and skipped by Obsidian Sync-style tools. Keep synced data in non-hidden names.

### Recommended file-format rules

1. **Per-device log segments.** Chat events go in `chats/<chatId>/events/<deviceId>/<segmentULID>.jsonl`, appended only by the device that created the segment. Start a new segment on every launch and seal it at about 1 to 4 MB, so a device restored from backup never appends to a log another copy of itself already extended.
2. **Event shape.** Every event carries a ULID and an HLC timestamp. Merge is a set union by ID, ordered by (HLC, deviceId), and replaying an event twice is harmless. Parse only newline-terminated lines.
3. **Write-once blobs.** Attachments, images, and agent outputs are named by content hash or ULID and never modified. Deletes are tombstone events, with garbage collection later.
4. **Derived Markdown.** The rendered chat copy is never authoritative. Render it deterministically from the merged log, so concurrent renders produce identical bytes, and delete conflict copies of derived files on sight.
5. **Settings.** Per-device files, or set-operations in the log with last-writer-wins per key by HLC. Never a single JSON file rewritten by every device.
6. **User-editable Markdown** (memories, topic instructions):
   - Keep a base hash and base copy in the local cache, and three-way merge (line based, like Joplin) when the file changes underneath.
   - Scan for the conflict-copy patterns above and fold them in.
   - On Apple platforms, also check `NSFileVersion` conflict versions through native code.
7. **Nothing database-like in the folder.** No SQLite, WAL, lock files, or caches. The index lives per device and can be rebuilt from the folder.
8. **Atomic writes.** Write to a same-directory temp file named like `.~<name>.tmp`, fsync, then rename. Sweep stale temp files.
9. **Names.** IDs rather than titles, lowercase ASCII, no reserved names or characters, each segment at most 255 bytes, and full paths well under 260 characters. No symlinks, no macOS packages, no case-only differences.
10. **Folders.** Never use folder location as identity (topics are data, not folder moves). Keep fewer than a few thousand entries per directory and the total well under 100k files.
11. **Placeholders.** Check placeholder state before reading, never bulk-read at startup, and fetch lazily.
12. **Format version.** Write a format version file with a minimum app version, like Joplin's `info.json`, so an old app on another device stops rather than corrupts.
