# Plans

Execution plans for non-trivial work, checked in so an agent can pick one up later with full context. One Markdown file per plan, all in this folder, whatever state it is in, so a link to a plan never breaks.

The first line under the title is the plan's status, in a fixed form `scripts/docs.ts` checks:

```text
Status: <open|done|superseded|dropped>. <Where it stands and what is left.>
```

- `open`: not finished, whether proposed, under way or paused.
- `done`: built, even if parts were reshaped on the way or later.
- `superseded`: overtaken by a different design; say what replaced it.
- `dropped`: abandoned with nothing (or nothing lasting) built.

After the state, be specific: "phases 1-3 landed, phase 4 not started" is worth more than "in progress", because it is the only line most readers check before deciding whether the rest is trustworthy. Cite the commits that carried the work. When work lands, update the plan's status in the same change. A finished plan stays here, with its status saying so, so the rationale stays legible.

To find plans: `rg -m1 '^Status: open' docs/plans` lists the open ones with their status; the index below has every plan.

Wireframes are working artifacts drawn with the `wireframe` skill and the Studio kit in [`.agents/wireframe-kit/`](../../.agents/wireframe-kit/KIT.md), and live outside the repository. A plan says in its own prose what a wireframe settled rather than linking one. `wireframes-*.html` beside the plans stays gitignored, so one written here by habit is never committed.
